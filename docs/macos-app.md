# macOS App 规划

> 状态：整理于 2026-11-02，2026-11-03 更新。第一期已在 [`macos/`](../macos/README.md) 实现；功能列表的「来源」一栏指的是规划时的情况。旧的菜单栏 App 见 [README](../README.md#mac-菜单栏-app)。

## 目标

Mac 全天录音并作为主力设备：在电脑前时直接实时转录，不等手表；离开电脑时由手表继续录，音频回到 Mac 后补上空缺。所有录音都能在 Mac 上查看、搜索，点转录段落就能跳到对应位置回放。

## 已定决策

| 主题 | 决定 |
| --- | --- |
| 录音方式 | Mac 全天录音，不做在场检测和手表蓝牙探测 |
| 麦克风 | 默认使用内建麦克风，避免录音时 AirPods 切到通话模式导致播放变声 |
| 系统声音 | 只录清单内的 App。默认选中会议 App，用户可增减；浏览器和微信默认不选 |
| ASR 模型 | 按需下载，只用第三方源，不自建 |
| 回传 | 可开关。iPhone 连上 Mac 后才自动转发，不要求实时 |
| 合并 | 确认内容相同才合并，默认保留 Mac 音频，并补上 Mac 没录到的时段；内容不同则都保留 |
| 回放 | 单击句子直接从这句播放；拖选文字可复制，右键菜单也有「复制」 |
| 功能范围 | 不再要求 iPhone 有过的功能 Mac 都要有，按场景分两期，见「分期」 |
| 系统要求 | 第一期要求 macOS 26 和 Apple 芯片，转录和总结都在本机完成，不上传 |
| 说话人 | 第一期只分「我」「会议对方」「他人」：麦克风里是我的声音算「我」，会议 App 那一路算「会议对方」，麦克风里的其他人算「他人」。具体人名和记住声音在第二期 |
| 会议要点 | 会议结束后几分钟内生成，不等整点。起止时间按实际说话从日历时间延长或缩短，可手动调整；没有日历的对话也能手动标成一场会议 |
| 不考虑 | 插电和低电量调度、MacBook 掉电和发热 |

## 系统限制

- **手表不能直连 Mac。** watchOS 限制底层网络（[TN3135](https://developer.apple.com/documentation/technotes/tn3135-low-level-networking-on-watchos.md)），Apple 工程师也说手表用 `URLSession` 访问局域网地址默认不通（[论坛](https://developer.apple.com/forums/thread/785846)）。音频走「手表 → iPhone → Mac」。
- **手表没有摄像头，也不能在后台开始录音。** 配对由 iPhone 扫码后转告手表；手表一旦停止，离开电脑时无法自动重新开始，所以手表要全程录。
- **Mac 休眠或合盖时录不了。** 合盖时内建麦克风不可用，这段由手表补上。
- **iPhone 连上 Mac 时，系统应该不会专门唤醒 App。** 转发时机是打开 iPhone App、手表分段到达时的后台唤醒，以及系统后台刷新。手表全天录音的续航和「手表 → iPhone → Mac」回传已在真机验证可行。
- **手表解锁 Mac 的逻辑不能复用。** 没查到第三方可用的距离接口。
- **系统声音只能按 App 录。** 同一浏览器分不出标签页；要按 bundle ID 前缀匹配，因为飞书等 App 的声音可能来自 helper 进程。
- **系统声音不包含用户自己的声音。** 用户的声音由麦克风那一路录下。麦克风全天录音，不受会议 App 静音影响，只能靠全局暂停避免。

## 界面规则

- **时间轴：** 活跃图和音轨都按 0–24 点画，比例一致；播放时音轨就是活跃图的展开层。
- **颜色：** 系统强调色只用于选中、链接和可点的东西。音频来源用固定色：Mac 深蓝灰、会议 App 青色、手表橙色。重点事件用紫色。说话人名字不上色。
- **活跃图的空状态：** 没录音是虚线，录了但没人说话是浅灰短条，标为私人是斜纹，已删除是虚线框，手表音频还没回来的小时加橙色虚线框（第二期）。录不了的时段画成没录音，对应的小时写明原因。图例不常驻，收在「每小时」标题旁的说明按钮里，只常显「重点事件」这一个色块。
- **异常：** 录不了时，主窗口顶部出现横幅，说明原因并给修复入口，和菜单栏的提示一致。
- **快捷键：** ⌘F 搜索，⌘[ 和 ⌘] 切换前一天和后一天，⌘T 回到今天，⌘E 导出这一天，空格播放或暂停，← 和 → 后退或前进 15 秒，⌃⌥P 暂停录音。焦点在输入框或纪要编辑框里时，空格和方向键交给输入框。获得焦点的元素显示焦点环。
- **点句子：** 单击播放；拖选文字时不播放，方便复制。
- **删除：** 用 macOS 标准确认框，写明会删掉多少分钟；「取消」是默认按钮，按 Esc 取消。
- **私人和删除的时段：** 在活跃图、音轨、搜索和提问里都不可点、不出现。当天总结里只要一条引用落在这些时段，这一条就重新生成，不保留。
- **窗口：** 最小宽度约 900 pt。窗口变窄时先收起侧边栏，再把右侧面板改成覆盖在内容上方，工具栏放不下的按钮收进「»」，不换行。

- 手表蓝牙探测和在场检测。
- 多台 Mac 之间同步。

- 待办和决定的提取与列表。
- 周视图和周报，留到后续版本。

## 实现要点

- **存储：** 现在的 PCM 单声道每小时约 173 MB。改成手表现用的 32 kbps AAC 后约每小时 14 MB，每天录 12 小时约 170 MB。静音段先保留音频，只跳过转录，因为手表静音置零的阈值还没验证过会不会丢轻声。
- **时间线：** 手表分段带 `startedAt`，但 `WatchRecordingImporter` 合成时只累加时长，写入失败后时间会偏移。合并时要改用真实时间，并用重叠音频校准时钟。
- **原始分段：** iPhone 现在合成后就删除收件箱，要改成 Mac 确认收到后才删除。
- **暂停、删除和私人：** 手表无法从 Mac 暂停，所以按时间段记录这些操作，手表和 iPhone 的音频回传时，落在这些时段里的内容直接丢弃，不转录、不合并。删除先进最近删除，30 天后在所有设备上彻底删除。
- **会议外放：** 用外放开会时麦克风也会录到对方，转录要去重。
- **总结更新：** 每小时结束后生成这一小时的总结，当前小时可先给临时结果。手表音频晚到时，只重新生成受影响的小时，再更新重点事件和每天总结。跨小时的会议在重点事件里仍算一件事。
- **配对：** 二维码和 Bonjour 的旧代码可从 `9d1c78a` 之前的版本参考，但旧方案是明文 HTTP 加长期令牌，不能原样恢复。
- **系统版本：** 第一期最低 macOS 26 和 Apple 芯片，用 `SpeechAnalyzer` 转录、Apple 智能总结，可另外下载第三方模型提高准确率。是否支持 macOS 15 留到第二期和第三方 AI 一起决定。
- **说话人：** 第一期不做声纹。麦克风这一路默认是「我」，只在检测到另一个人的声音时标成「他人」，需要轻量的说话人切换检测。
- **隐私：** 全天录音会录到别人，不同地区对录音同意的要求不同，首次开启时要提示，上线前要确认法律要求。

## 待验证

| 问题 | 影响 |
| --- | --- |
| 按 App 录音能否录全飞书和腾讯会议的声音 | 系统声音清单的匹配规则 |

| 声纹阈值在真人、远场和嘈杂环境下是否可用 | 文档里只用合成语音测过 |
| 候选 ASR 模型的中文准确率和速度 | 默认模型的选择 |
